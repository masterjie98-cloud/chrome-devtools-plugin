# Agent 运行架构 P0/P1 实施计划

更新时间：2026-08-05

## 当前目标

先修复 MCP 工具结果返回后 Agent 永久停留在“等待 AI 分析”、计时不更新和后续启动超时的问题；随后完成下列 4 个 P0 与 4 个 P1，最后统一进行类型、测试、构建、打包和真实浏览器验收。

## 已确认的卡死根因

1. Provider 在报告生成阶段持续重复输出同一条内部约束句，连接一直有新字节，因此旧的空闲超时永远不会触发。
2. 等待计时器在收到首个模型片段后停止刷新，UI 会永久停在 `0s`，掩盖仍在进行的异常长流。
3. 未配置 `maxOutputTokens` 时请求体没有实际输出上限，也没有绝对总时长、流字节上限或退化复读检测。
4. 原运行未结算时，同一对话的新请求会被 daemon 的单运行互斥拒绝，最终表现为“启动 daemon Agent 超时”。

- [x] 结构化 `AgentRun -> Turn -> ToolCall`，聊天消息只作为可重建的展示投影。
- [x] 持久化阶段、心跳、最后进展与安全诊断，明确区分运行、等待 Provider、等待工具、等待审批、停滞和终态。
- [x] 采集 Provider 返回的真实 Token 使用量；不支持真实 usage 时明确标记估算；记录每次上下文压缩的原因和前后变化。
- [x] 将脱敏后的运行诊断证据持久化，支持重载/重连后解释“为什么停、停在哪里、能否安全恢复”。
